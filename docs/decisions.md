# 已确认的设计决策

本文记录已经确认并会影响后续开发的选择。新决策请追加日期、背景、结论和影响；不要把一次性的调参结果直接当成架构决策。

## D-001：代码项目与 Obsidian Vault 分离

- 日期：2026-10-12
- 决策：代码、配置、测试和经过确认的项目文档放在代码仓库；Obsidian Vault 只保存整理后的知识。
- 原因：避免 debug 输出、日志、临时代码和大体积实验产物进入知识库。
- 影响：Codex 默认只访问 `D:\Unet`；只有用户明确要求时才读取 Vault。

## D-002：项目内维护小型知识索引

- 日期：2026-10-12
- 决策：稳定知识先维护在 `docs/`，当前索引文件为 `architecture.md`、`decisions.md`、`current-state.md` 和 `troubleshooting.md`。
- 原因：让日常开发只需要读取少量上下文，并保留可审查的项目内来源。
- 影响：同步到 Vault 以复制或整理为主，不把 Vault 当作运行时输入。

## D-003：输入采用轮廓 + 实体 mask 双通道

- 决策：模型输入不是单通道轮廓，而是轮廓和填充后的实体区域 mask。
- 影响：旧 checkpoint 不兼容；输入定义变化后必须重新执行数据准备，并从 B 预训练开始。

## D-004：按 group 划分并绑定重复内容

- 决策：A/B 和同组 distance 不跨 train/validation/test；相同输入内容的 group 也绑定在同一集合。
- 原因：降低同源样本和图像重复造成的数据泄漏。

## D-005：标签计数与设计计数分离

- 决策：训练标签计数由半截面标签连通域统计；工作簿中的红/绿/蓝计数视为完整截面设计计数，仅用于条件特征和元数据。

## D-006：推理默认不镜像

- 决策：推理保持半截面到半截面，不自动生成完整截面点分布。
- 影响：任何需要完整截面的镜像操作必须由明确的后处理流程和参数控制。

## D-007：先使用文件夹同步，不引入 MCP

- 决策：当前采用代码项目 `docs/` 与 Vault 目录之间的按需人工复制/整理；暂不配置 Obsidian 插件或 MCP。
- 原因：当前知识规模尚小，直接文件夹访问更容易审查权限和边界。
- 复评条件：当笔记规模需要按标题、标签或关键词检索时，再评估 MCP。
